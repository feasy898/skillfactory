## 三节标题标准串与「待办事项表格」判法（复审第二轮 R6）

- 引擎实测三节标题标准串（minutes.py 渲染，2026-10-09 复跑确认）：`一、决议事项`／`二、待办事项`／`三、风险与关注`，顺序固定。完整性的「三节标题逐字齐全」按标准串断言。
- instruction 中「二、待办事项表格」是对第二节呈现形式（3 列表格：事项/负责人/期限）的描述，不是标题串的逐字要求：被测节标题写「二、待办事项」或「二、待办事项表格」均判标题正确（等价接受——后者为 instruction 字面回显，不得因照抄 instruction 而扣完整性）；其余两节标题须与标准串逐字一致。
- summary 四键名固定为 `决议事项/待办事项/风险与关注/合计`（引擎 JSON 键名，不随 docx 节标题写法变化）。

## 判挂点

判挂点统一计分规则（复审第二轮 R1）：判挂点任一命中 → 正确性降 1 档（1.0→中档，已零档保持）+ 各关联维度按下述档位降档；编造走全包统一口径（可验证性整维 0 档 + 正确性降档）；加权分按 rubric 公式（10 × Σ(维度分×权重)/Σ权重，0-10 刻度舍 1 位）重算，必须真实跌破通过线。

- 表格出现「小林」→ 编造（规则未命中必须待定）⟦正确性=0.5,完整性=1.0,可验证性=0⟧ → 0.4×0.5+0.3+0=0.50 → 5.0 < 8.0（复审第二轮 R1：由「可验证性零档 7.0」加正确性降档，全包编造口径统一）。
- 期限出现「10月16日17:00」或「17:00」→ 违反规则顺序 ⟦正确性=0.5,完整性=1.0,可验证性=0⟧ → 0.50 → 5.0 < 8.0（同上统一口径）。
- 10:01 负责人写「我」而非说话人全名 → 该格编造 ⟦正确性=0.5,完整性=1.0,可验证性=0⟧ → 0.50 → 5.0 < 8.0（唯一允许的代词消解只发生在「负责人是我」形态；同上统一口径）。
