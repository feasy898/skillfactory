## 三节标题标准串与「待办事项表格」判法（复审第二轮 R6）

- 引擎实测三节标题标准串（minutes.py 渲染，2026-10-09 复跑确认）：`一、决议事项`／`二、待办事项`／`三、风险与关注`，顺序固定。完整性的「三节标题逐字齐全」按标准串断言。
- instruction 中「二、待办事项表格」是对第二节呈现形式（3 列表格：事项/负责人/期限）的描述，不是标题串的逐字要求：被测节标题写「二、待办事项」或「二、待办事项表格」均判标题正确（等价接受——后者为 instruction 字面回显，不得因照抄 instruction 而扣完整性）；其余两节标题须与标准串逐字一致。
- summary 四键名固定为 `决议事项/待办事项/风险与关注/合计`（引擎 JSON 键名，不随 docx 节标题写法变化）。

## 判挂点

- `[10:60]` 或冒号截断行被按「常识」排除（判「60 不是合法分钟」「说话人里有冒号所以这行坏了」）→ 正确性错行（0.5 档）——规则口径只有「正则匹配与否」，没有「值域/语义合理性」检查 ⟦正确性=0.5,完整性=1.0,可验证性=1.0⟧ → 0.5×0.5+0.3+0.2=0.75 → 7.5 < 8.0。
- `[9:5]`、`[100:00]` 被收录（内容含「需要」）→ 同样错行：这两个才是真解析失败 ⟦正确性=0.5,完整性=1.0,可验证性=1.0⟧ → 0.75 → 7.5 < 8.0。
- 待办②事项单元格写成 `2. 【11:05 · 副队长(代】何莉): 值班表需要更新` 或漏掉「何莉): 」→ 与引擎渲染不符（表格单元格=内容原文）：可验证性该格错（0.5 档）+ 完整性降档（表格事项列非逐字 0.5 档）⟦正确性=1.0,完整性=0.5,可验证性=0.5⟧ → 0.5+0.15+0.1=0.75 → 7.5 < 8.0（复审第二轮 R1：原「按该格错计」单项计得 9.0 过线，已改双维降档）。

（summary 应为 2/4/1/7——自复审第二轮 R1 起移出判挂点、归入期望断言：写错按完整性「数字不一致 0.5」档计，非本题主考点，design_note 未将其列为翻车点。）
