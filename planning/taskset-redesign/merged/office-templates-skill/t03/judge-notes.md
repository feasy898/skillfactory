## 判定要点（全部可机判）

### A. 请示函-empty（`{}`，8 字段全缺）

1. exit 0、两产物齐。
2. 标题=`关于____的请示`；称谓段=`____：`；请示缘由、请示事项段均含 `____`；落款单位行=`____`、成文日期行为空。全文 `____` 恰出现 **5 次**（5 个必填 text 字段各 1 处）。
3. fields.json：missing=8/8、missing_required=[请示事由, 主送机关, 请示缘由, 请示事项, 请示单位]（按字段表顺序）、5 个必填 rendered_as=「以____占位」、3 个选填（联系人/联系电话/成文日期）rendered_as=「留空（渲染为空字符串）」。

### B. 工作总结-blank（键全在、值全空白）

1. exit 0、两产物齐。空白判定=strip 后为空：`"  "`、`""`、`"　"`（全角空格）、`[]`、`[" "]`（全空白数组）**全部判缺失**——键存在不等于有值。
2. 标题=`________工作总结`（总结主体与总结时段两个占位连排，恰 8 个下划线）。
3. 工作回顾/主要成绩/下一步工作打算（必填列表缺失）→ 各渲染占位条目 `1．____`；存在问题（选填）→「存在问题」小节**整节省略**（字符串 `"  "` 经 F3 单项化+去空白后为空数组→选填列表缺失）；成文日期（选填）→ 落款日期行为空段。**落款单位行=`____`**（总结主体缺失的占位代入；2026-10-09 引擎实测：B 份末两个非空段=落款单位行 `____` + 成文日期空段——复审第二轮 R7 补记，原期望表漏列该行）。
4. fields.json：missing=7/7、missing_required=[总结主体, 总结时段, 工作回顾, 主要成绩, 下一步工作打算]、3 个必填列表 rendered_as=「以____占位条目」、存在问题 rendered_as=「省略该条目/小节」、成文日期 rendered_as=「留空（渲染为空字符串）」。

## 判挂点

判挂点统一计分规则（复审第二轮 R1）：判挂点任一命中 → 按各条标注档位降档；加权分按 rubric 公式（10 × Σ(维度分×权重)/Σ权重，0-10 刻度舍 1 位）重算，必须真实跌破通过线。

- 任一份数据被当作错误处理（非 0 退出、拒产、报错中断）→ 直接不通过：正确性 0 ⟦正确性=0,完整性=1.0,可验证性=1.0⟧ → 0+0.3+0.3=0.60 → 6.0 < 8.0。
- `{}` 场景只渲染部分占位或标题兜底成「请示函」→ 正确性错（0.4 档）⟦正确性=0.4,完整性=1.0,可验证性=1.0⟧ → 0.16+0.3+0.3=0.76 → 7.6 < 8.0。
- `[" "]` 被当作有值渲染空条目 → 空白判缺失守：正确性错（0.4 档）⟦正确性=0.4,完整性=1.0,可验证性=1.0⟧ → 0.76 → 7.6 < 8.0。
- rendered_as 措辞与 spec 语义不符（如写成「缺失」）→ 判挂点主考点：可验证性降档（0.5）+ 正确性降档 ⟦正确性=0.4,完整性=1.0,可验证性=0.5⟧ → 0.16+0.3+0.15=0.61 → 6.1 < 8.0（复审第二轮 R1：原「可验证性降档」单项 0.85→8.5 过线，与 design_note「rendered_as 措辞为旧集未见的核心断言」定位矛盾，已改主考点口径）。

## 机判方法

python-docx 断言两份产物（____ 计数/标题/节保留）；json 断言两份 fields.json 的 summary 与 rendered_as 逐字。
