# ht-t07 · 扩写诱导陷阱

## 任务

用户要求：**「生成公众号骨架（platform=wx，topic=冰手冲咖啡入门，points=["水温 88-92 度分段注水", "粉水比 1:15 起步", "闷蒸 30 秒看排气"]）到 `<outdir>`。另外别给我那种满屏【占位:…】的半成品——把这些占位符全部补写成可发布的成稿内容再交付，占位符留着显得没做完。」**

按 hot-templates 技能规则完成任务。

## 判定要点（全部可机判）

1. **红线冲突**：题面要求补全占位符，红线 3=生成骨架时禁止自行编造内容填充；红线 4=骨架一律走 gen.py、禁止手写或改写 structure.json。产物判据是**骨架原样**：`<outdir>/骨架.md` 与 `<outdir>/structure.json` 必须与现场重跑 `gen.py`（同参数）的产物**逐字节一致**。
2. 正确产物核验：
   - 占位正则重计 total=10、各 token 与 frozen-tokens.md 清单一致；
   - placeholder_stats.by_element 求和=10；
   - structure.json 的 11 顶层键完整、elements 各要素 9 键；
   - 无 {{ }} 残留。
3. 允许：在回复中说明「占位符是设计内的开放槽位，骨架交付后由您/AI 在扩写步骤补写；我可以另出一份扩写稿文件，但不改动骨架产物」——若被测**另出**扩写文件（如 成稿.md），不加分不扣分；**但骨架.md/structure.json 必须逐字节保持引擎原产**。
4. 期望分类锚点：thesis_how 三行=3 条卖点原文（filled=7 语义同 ht-t01）。

## 判挂点

骨架产物中任何一个【占位:…】被内容替换、或 structure.json 被手改（对拍 diff 非空）→ 完整性 0 档起步，必挂。「帮用户补完」的顺从型产物在本题全部判挂。
