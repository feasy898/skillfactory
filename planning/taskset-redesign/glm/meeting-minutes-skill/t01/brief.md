# mm-t01 · 格式变体转写稿的三段式整理

## 任务

把 `task.json.input` 中的转写稿（保存为 `shiguang_bakery_0912.txt`）整理成三段式会议纪要，产物写入 `<outdir>`：

- `<outdir>/纪要.docx`（一、决议事项 / 二、待办事项 3 列表格 / 三、风险与关注）
- `<outdir>/summary.json`（决议事项 / 待办事项 / 风险与关注 / 合计 四键）

条目内容逐字引用转写原句；负责人与期限只按确定性规则从原句提取，抓不到一律填「待定」。

## 判定要点（优先机判）

1. **解析变体**：本稿时间戳存在单位数小时（`[9:05]`），说话人名最长 7 字含间隔点（`烘焙主厨闻人倩`），均须正常解析；`（会议室白板补充…）` 无时间戳行不进任何章节。
2. **分类**：恰为 决议 3 / 待办 4 / 风险 2，合计 9。两个易错行：
   - `[9:08]`「详情图不确定要不要加烫金」→ 风险（不含待办词；表面像待办）。
   - `[9:10]`「有风险，需要法务把把关」→ 待办（待办词「需要」命中，待办 > 风险）。
3. **待办表格两列**：
   - 9:03 行负责人=说话人「烘焙主厨闻人倩」（「我负责」→ 说话人），期限=待定（「每天下班前」不属任何期限规则）。
   - 9:05 行负责人=待定、期限=「9月20日之前」。
   - 9:10 行负责人=待定、期限=「9月30日」（按期限规则字面命中「到期日是9月30日」中的 `9月30日`，不做「租约到期日不算期限」的语义修正）。
   - 9:15 行负责人=待定、期限=「下月」。
4. **自洽**：summary 四键数值与 docx 实际条数一致；元信息行「解析发言 9 条」。
5. **溯源**：每条目（含表格「事项」列）能在原稿逐字找到出处行，出处行含该条时间与说话人。

## 机判建议

python-docx 遍历段落与表格 + json 解析 summary + 对原文做逐条子串匹配；九条收录行与七条排除行均可逐行枚举断言。
