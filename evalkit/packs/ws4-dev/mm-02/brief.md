# 任务：为一场记录不规范的会议整理三节式会议纪要

## 输入

- `fixtures/transcript.txt`：一场会议的转写稿。**注意两点记录缺陷**：
  1. 全稿**没有时间戳**；
  2. 存在**同名说话人**（同一姓名可能对应不止一位与会者，稿内无任何区分标记）。

## 输出（写到 `out/` 目录）

**1. `out/纪要.docx`（Word 文档）**

- 第一段为纪要标题（自拟，含会议主题即可）；
- 正文依次包含三节，节标题必须逐字为：`一、决议事项`、`二、待办事项`、`三、风险与关注`；
- 「决议事项」「风险与关注」两节的条目编号列出，每条格式逐字遵循：

  ```
  N. 【类别 · 相关人】内容
  ```

  其中 `类别` 为 `决议事项` 或 `风险与关注`；`相关人` 必须是转写稿中出现过的说话人姓名；
  `内容` 必须与转写稿中某句话逐字一致（不含句末句号也可以）。
  **同名归属处理**：当条目相关人恰为同名说话人、无法唯一归属时，在该条目内容末尾追加 `（归属待核）` 四字后缀；可唯一归属的条目不加。
- 「待办事项」用表格呈现：表头三列逐字为 `事项`、`负责人`、`期限`；一行一条待办；
  - `事项` 必须能在转写稿中逐字找到出处；
  - `负责人` 必须是转写稿中出现过的说话人姓名；
  - `期限` 取该条待办在转写稿中提到的时限；转写稿未提到时限的，`期限` 填 `未明确`（本稿至少有一条这样的待办）。

**2. `out/summary.json`**

```json
{"决议事项": <条数>, "待办事项": <条数>, "风险与关注": <条数>, "合计": <三者之和>}
```

四个键名逐字如上；计数必须与 docx 中各节实际条目数一致。

## 纪律（判定即按此执行）

- 以转写稿为**唯一事实来源**：不得编造任何决议、待办、风险、人名；
- **禁止补造时间戳**：转写稿没有 `[HH:MM]` 形式的时间，纪要中出现任何 `[HH:MM]` 形式的时间即判不合格；
- **禁止虚构说话人区分**：不得给同名说话人发明「甲/乙/部门」等区分标记；
- 归纳、改写、概括均视为不可溯源，会被判不合格——条目内容必须逐字取自转写稿。

## 环境

- 可用 Python（python-docx 已安装）生成 docx；无需联网。
